# Experimental Claude Code runtime

The local proof of concept uses the official TypeScript Agent SDK `0.3.319` and an explicitly selected, Anthropic-signed Windows x64 Claude Code `2.1.319` executable. Set `STUDIO_EXPERIMENTAL_CLAUDE_CODE=1` before launching Studio. Other executable versions and architectures require qualification.

In **Settings → AI → Providers → Claude Code Runtime**, enter an absolute path to `claude.exe` and optionally an absolute configuration directory. The connection status reports the executable version and the native auth method when available. **Sign in with Claude Code** opens the vendor's native sign-in in a terminal. **Disconnect Claude runtime** retires Studio's connection and interrupts its active turns. The native login and settings stay on the machine.

On a local site, **New Claude Code chat** asks for a saved connection, a model and an effort reported by that runtime. The chat stays attached to that connection, local site, canonical workspace and native configuration directory. A new selection takes effect on the next turn. Missing or ambiguous native history requires starting a new chat. Studio keeps its display journal separately and clears it when the chat is deleted. Claude Code owns its native transcript. After an unexpected process death, a persisted lock can require manual recovery. Confirm the earlier process has exited before starting another chat.

The CLI exposes the same connection operations through `studio code claude`. Use `configure --executable <absolute-path>`, `status`, `models --connection <id> --site <site-id>` and `new --connection <id> --site <site-id> --model <id> --effort <level>`. Use `select --session <id> --model <id> --effort <level>` before resuming with `studio code sessions resume <id> <message>`. Draft requests in an interactive terminal require explicit approval. JSON mode without a Studio parent denies draft requests.

Each run checks the native configuration, reports routing conflicts and compares the vendor's startup account and tool inventory before sending input. Reported first-party Claude.ai sign-in and matching Pro or Max plan evidence qualify this path for the experiment. The evidence can be inconclusive. Studio has no billing attestation. A refusal ends the turn on that connection.

The selected executable runs with a restricted inventory. The native `Read` hook checks the bound workspace and rejects common sensitive paths. Studio's tool allows selected local WP-CLI reads and a bounded draft-post creation. The draft approval identifies the site, title and content. The host rechecks the site, connection, cancellation and WP-CLI configuration before launch. Native shell and edit tools are disabled. The WP-CLI process can load local WordPress and must-use plugin code. These checks assume a trusted local workspace and cannot establish filesystem isolation. The SDK reports full plugin and runtime init metadata after input is released. Studio blocks tool calls until that frame passes verification.

Native startup, model capability discovery, authenticated model and site testing, installed-app qualification and public distribution are separate gates. Public distribution requires use-case-specific Anthropic clarification or approval, or a separately designed API or supported-cloud product path.
