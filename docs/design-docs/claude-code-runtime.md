# Experimental Claude Code runtime

The local proof of concept uses the official TypeScript Agent SDK `0.3.319` and an explicitly selected, Anthropic-signed Windows x64 Claude Code `2.1.319` executable. Set `STUDIO_EXPERIMENTAL_CLAUDE_CODE=1` before launching Studio. Other executable versions and architectures require qualification.

In **Settings → Providers**, under **Claude Code Runtime**, enter an absolute path to `claude.exe` and optionally an absolute configuration directory. The connection status reports the executable version and the native auth method when available, followed by any blockers and findings as short codes. **Recheck status** runs the inspection again. **Sign in with Claude Code** opens the vendor's native sign-in in a terminal. **Disconnect Claude runtime** retires Studio's connection and interrupts its active turns. The native login and settings stay on the machine.

On a local site, **New Claude Code chat** asks for a saved connection, a model and an effort reported by that runtime. The chat stays attached to that connection, local site, canonical workspace and native configuration directory. A new selection takes effect on the next turn. Missing or ambiguous native history requires starting a new chat. Studio keeps its display journal separately and clears it when the chat is deleted. Claude Code owns its native transcript. After an unexpected process death, a persisted lock can require manual recovery. Confirm the earlier process has exited before starting another chat.

Creating a chat or sending a message waits for successful, settled connection and model checks. A failed refresh, removed connection or unsupported effort holds the prompt. Model and effort changes require selecting an option; capability refreshes and closing a picker cannot silently restore an earlier choice. A draft approval belongs to the current run. Reconnecting recovers its outstanding requests, while a completed or interrupted run clears them.

The CLI exposes the same connection operations through `studio code claude`. Use `configure --executable <absolute-path>`, `status`, `models --connection <id> --site <site-id>` and `new --connection <id> --site <site-id> --model <id> --effort <level>`. Use `select --session <id> --model <id> --effort <level>` before resuming with `studio code sessions resume <id> <message>`. Draft requests in an interactive terminal require explicit approval. JSON mode without a Studio parent denies draft requests.

Each run checks the native configuration, reports routing conflicts and compares the vendor's startup account and tool inventory before sending input. A Studio process started from a terminal inside a Claude Code session inherits `ANTHROPIC_BASE_URL`, for example, and lists it as a blocker. Reported first-party Claude.ai sign-in and matching Pro or Max plan evidence qualify this path for the experiment. The evidence can be inconclusive. Studio has no billing attestation. A refusal ends the turn on that connection.

The selected executable runs with a restricted inventory. The native `Read` hook checks the bound workspace and rejects common sensitive paths. Studio's tool allows selected local WP-CLI reads and a bounded draft-post creation. The draft approval identifies the site, title and content. The host rechecks the site, connection, cancellation and WP-CLI configuration before launch. Native shell and edit tools are disabled. The WP-CLI process can load local WordPress and must-use plugin code. These checks assume a trusted local workspace and cannot establish filesystem isolation. The SDK reports full plugin and runtime init metadata after input is released. Studio blocks tool calls until that frame passes verification.

Native startup, model capability discovery, authenticated model and site testing, installed-app qualification and public distribution are separate gates. Public distribution requires use-case-specific Anthropic clarification or approval, or a separately designed API or supported-cloud product path. Two parts of this experiment need that clarification in particular. It accepts only a stored first-party Claude.ai sign-in on a Pro or Max plan and refuses a runtime routed through an API key, a gateway or a cloud provider, while Anthropic's conditions for running Claude Code inside a product keep its built-in authentication methods unrestricted. Its interface labels use the Claude Code name, which the same conditions keep out of product and feature names. [Anthropic legal and compliance](https://code.claude.com/docs/en/legal-and-compliance) · [Claude plan and SDK guidance](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan)

For offline Windows lifecycle qualification, set `STUDIO_TEST_NATIVE_CLAUDE_LIFECYCLE_EXE` to the absolute path of the signed `2.1.319` executable and run `npm test -- packages/agent/node/claude-code/tests/native-lifecycle.test.ts --maxWorkers=1`. The opt-in suite uses an empty native profile and the real SDK/Studio launcher, blocks user messages, and checks SDK close, abort, stdin EOF, native termination and owner termination. It also verifies terminal-journal handling and that no descendant process survives. This does not exercise authenticated inference. Observed outcomes and remaining acceptance are recorded in the [implementation plan](../superpowers/plans/2026-11-08-claude-runtime-implementation.md#observed-completion--november-10-2026).
